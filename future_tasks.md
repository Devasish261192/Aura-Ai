## 4. Multi-Tenant Concurrency & Anti-Hallucination Architecture

To scale safely to **100+ concurrent active users** without cross-talk or hallucinations:

```
[User Request] ──► [JWT Auth Middleware] ──► [Worker Thread] ──► [Tenant DB Partition]
                                                    │
                                                    ▼
                                    [Ephemeral LLM Call (Temp 0.2)]
                                                    │
                                                    ▼
                                    [Strict Tool Schema Validation]
```

### Concurrency & Data Isolation Rules
1. **Cryptographic Identity (JWT):** Every request authenticated via signed JWT containing unique `user_id` (UUIDv4). Plain client-supplied session IDs are never trusted.
2. **Database Row-Level Isolation:** All queries strictly scoped: `WHERE user_id = :authenticated_user_id`.
3. **Artifact Sandboxing:** Separate file directories per tenant: `data/artifacts/{user_id}/`.
4. **Stateless Request Handlers:** In-memory chat objects are strictly ephemeral. No shared global dictionaries across async worker threads.

### Anti-Hallucination Guardrails
1. **Scribe, Not Author:** System prompt strictly forbids fabricating facts, metrics, or technologies not explicitly stated by the user.
2. **Deterministic Function Calling:** Vault updates only happen via typed tool calls (`save_career_story_entry`, `save_work_experience_entry`).
3. **Micro-Context STARR Constraint:** Asking for one point at a time prevents LLM cognitive overload.
4. **Low Temperature:** Enforce `temperature = 0.2` across all inference calls.
5. **Human-in-the-Loop Mirror:** Immediate visual rendering of the generated JSON on the split-screen viewer for live user inspection and correction.
